# Работа с FERDINAND

## Цель

Создавать рабочие инструменты пользователя по мотивам предоставленной презентации. Материалы проектирования находятся в docs/; machine-readable каталог — в catalog/tools.json.

## Обязательные правила

- Читать README.md, выбранный инструмент в каталоге и его механику перед изменением.
- Отделять факт из источника от предложения реализации; сохранять ссылки на страницы.
- Не объявлять инструмент работающим до реализации, проверки и подключения необходимых данных.
- Соблюдать статус evidence_level: screenshot_label подтверждает название вкладки, future обозначает будущее направление.
- Использовать обычный код для денежных расчётов, прав, переходов состояний и защиты от повторной обработки.
- Принимать неизвестные поля как неизвестные; сохранять очередь вопросов и источники.
- Не сохранять токены, пароли, реальные выписки и клиентские данные в Git.
- Выполнять внешние действия в рамках доступа и согласованного режима; учитывать уже полученное разрешение пользователя.
- Уточнять отсутствующие бизнес-правила до зависимой реализации; продвигать независимые задачи.
- Сначала выбрать один сценарий и измерить результат.
- Документы писать по-русски, имена программных сущностей выбирать понятными и устойчивыми.
- Не запускать подагентов без явного запроса пользователя или применимого обязательного указания.
- Для каждой задачи сначала называть штатный способ её решения: официальный API или выгрузку сервиса, встроенный браузер или Claude в Chrome с входом пользователя, подключаемый коннектор. Если просьба пользователя сформулирована через обходной путь (имитация, парсинг, вход по паролю), предлагать штатную замену и объяснять, почему она надёжнее. Пользователь просил говорить об этом всегда.

## Проверки

Проверять повторный импорт, неопределённые значения, происхождение данных, частичные сбои и ограничения доступа. Для вычислений использовать независимые ожидаемые значения и контрольные примеры. Обновлять каталог и документацию по итогам реализации.

## Контекст текущего этапа

Все инструменты имеют статус planned. Первой системой пользователь выбрал финансового помощника **Фил** по мотивам Рокфеллера. Фил ведёт только личные финансы. Механики описаны в docs/08-phil-mechanics.md; способы получения выписок Т-Банка — в docs/09-phil-tbank-statements.md. Конкретные счета, первая выписка, регулярное получение и технологический стек пока уточняются. Доступ к банку и почте не подключён. Проект содержит спецификации, контракты и источники.
